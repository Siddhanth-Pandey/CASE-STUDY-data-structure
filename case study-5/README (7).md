# City Navigation and Huffman Compression — Case Study

A beginner-friendly Python case study combining **graph algorithms** for city navigation with **frequency-based Huffman coding** and practical **GZIP/ZIP compression**.

## Problem statement

A navigation system needs to model intersections and roads, find a low-distance route between two locations, and identify locations reachable from a starting point. Separately, reports produced by the system can be compressed to reduce storage or transfer size.

## Objectives

- Represent a city map as a weighted, undirected graph.
- Use Dijkstra's algorithm to find a shortest route by distance.
- Use Breadth-First Search (BFS) to find reachable locations.
- Build a Huffman tree from character frequencies and generate prefix codes.
- Encode and decode a sample report with Huffman coding.
- Create standard `.gz` and `.zip` files using Python's standard library.

## Algorithms and data structures

### 1. Weighted graph

An adjacency dictionary stores each location and its neighbours with the road distance as the edge weight. This makes it straightforward to add roads and inspect neighbours.

### 2. Dijkstra's algorithm

Dijkstra's algorithm uses a min-priority queue to repeatedly explore the currently closest unprocessed location. It is appropriate here because all road weights are positive.

- Time complexity with a binary heap: commonly expressed as `O((V + E) log V)`.
- `V` is the number of locations and `E` is the number of roads.

### 3. Breadth-First Search

BFS traverses neighbours in layers and returns all locations reachable from a chosen start. In this project it checks connectivity, not shortest distance by kilometres.

- Time complexity: `O(V + E)` for an adjacency-list graph.

### 4. Huffman coding

Huffman coding counts character frequencies, repeatedly combines the two least-frequent nodes, and assigns `0`/`1` along tree edges. Frequent characters generally receive shorter codes. The example verifies that decoding reproduces the original report.

The demonstration prints the number of encoded bits and compares it with a simple 8-bit-per-byte baseline. It does not include a compact binary container for the Huffman tree, so that bit count is an algorithm demonstration rather than a complete on-disk compression ratio.

### 5. GZIP and ZIP

The script uses `gzip` and `zipfile` from Python's standard library. GZIP stores a single compressed stream; ZIP can package one or more files. Very small files may grow because headers and metadata add overhead.

## Limitations and possible extensions

- Road distances are illustrative and static; there is no live GPS, traffic, turn restriction, or geospatial map integration.
- Distances are used as weights. A production system could use travel time, traffic, tolls, or accessibility preferences.
- The Huffman implementation is educational and stores its report as JSON for inspection; a production codec should serialize the tree/frequency table and packed bits into a binary format.
- The example city graph is small. Larger road networks could use a graph library, spatial indexing, A* search with geographic heuristics, and real map data.
